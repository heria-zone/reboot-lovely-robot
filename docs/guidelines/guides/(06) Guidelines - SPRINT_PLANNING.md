# SPRINT_PLANNING.md - Guidelines

## Purpose
The SPRINT_PLANNING.md document organizes development work into focused, time-boxed cycles aligned with the strategic roadmap. It bridges the gap between long-term planning and day-to-day task execution by breaking the roadmap into manageable sprint cycles with clearly defined objectives, scope, and success criteria. This document provides the tactical framework that guides daily development activities while ensuring progress toward strategic goals.

## When to Create
- After establishing the ROADMAP.md document
- Before beginning active development
- When planning the next development cycle
- When transitioning from planning to execution phase
- When coordinating multiple developers or teams

## How to Approach

### 1. Define Sprint Cadence and Structure
- Establish sprint duration (typically 1-4 weeks)
- Define sprint ceremonies and checkpoints
- Create consistent sprint naming or numbering
- Determine capacity planning approach

### 2. Map Roadmap to Sprint Cycles
- Break roadmap milestones into sprint-sized chunks
- Sequence sprints to align with roadmap priorities
- Ensure each sprint builds toward milestone completion
- Balance feature development with infrastructure work

### 3. Define Sprint Success Criteria
- Establish measurable objectives for each sprint
- Set clear definition of done for deliverables
- Create acceptance criteria for sprint outcomes
- Define quality standards for sprint completion

### 4. Allocate Resources Effectively
- Consider skill requirements for sprint goals
- Balance workload across available resources
- Identify critical path dependencies
- Plan for potential bottlenecks

### 5. Incorporate Feedback and Learning
- Plan for sprint reviews and retrospectives
- Create mechanisms for adjusting subsequent sprints
- Establish sprint metrics for measuring improvement
- Include time for incorporation of feedback

### 6. Anticipate Risks and Challenges
- Identify sprint-specific risk factors
- Develop contingency plans for likely issues
- Establish go/no-go criteria for critical components
- Create fallback options for uncertain outcomes

### 7. Connect Strategy and Execution
- Maintain clear linkage to roadmap milestones
- Ensure business priorities guide sprint content
- Balance short-term deliverables with long-term goals
- Communicate strategic context to development team

## Tips for Effectiveness

- **Keep Sprint Goals Focused**: Limit objectives to what can realistically be achieved
- **Balance Types of Work**: Include features, technical debt, and infrastructure
- **Consider Full Delivery Cycle**: Account for design, development, testing, and documentation
- **Use Consistent Templates**: Establish standard formats for sprint documentation
- **Visualize Dependencies**: Create clear visuals for inter-sprint dependencies
- **Connect to Strategic Goals**: Link sprint objectives to broader roadmap milestones
- **Document Assumptions**: Note assumptions that influenced sprint planning
- **Allocate Slack Time**: Don't fill sprints to 100% capacity
- **Account for Overhead**: Include time for meetings, reviews, and coordination
- **Update Regularly**: Revise plans based on sprint outcomes
- **Incorporate Lessons Learned**: Apply retrospective findings to future sprints
- **Document Decisions**: Record key decisions that shape sprint content
- **Clarify Priorities**: Make it clear which items are must-haves vs. nice-to-haves
- **Define Exit Criteria**: Establish clear conditions for sprint completion
- **Plan for Integration**: Include time for component integration and testing

## Common Pitfalls to Avoid

- **Overcommitment**: Planning more work than can reasonably be completed
- **Ignoring Dependencies**: Not accounting for sequential requirements
- **Neglecting Unknowns**: Not leaving buffer for unexpected challenges
- **Fuzzy Objectives**: Having unclear or unmeasurable sprint goals
- **Feature Fixation**: Focusing only on features while neglecting technical foundations
- **Inadequate Preparation**: Not having backlog items sufficiently refined
- **Disregarding History**: Ignoring past velocity when planning future sprints
- **Neglecting Risk Management**: Not planning for likely complications
- **Abandoning Plans**: Dropping structure entirely when challenges arise
- **Rigid Adherence**: Not adapting sprint plans when conditions change
- **Disconnect from Roadmap**: Losing sight of how sprints connect to larger goals
- **Skipping Retrospectives**: Not learning from completed sprints
- **Multitasking Overload**: Assigning too many concurrent tasks
- **Missing Celebrations**: Not acknowledging achievements and progress
- **Documentation Debt**: Not maintaining sprint records for future reference
